# RUNBOOK — running the mention-stage evaluation

Followed verbatim when the user says **"run the mention eval"**. Read
`TAXONOMY.md` before judging anything and `README.md` if you do not already know
what this stage is.

**Standing authorization: spawn as many agents as the protocol needs.** One
judge agent per (subject, field), split at safe boundaries for large fields,
plus verification and corpus-seeding agents — this fan-out is the user's
explicit instruction, renewed by every "run the mention eval" request. Do not
hesitate; do not ask permission per agent.

**Judgment is EXHAUSTIVE by user decision.** Every snippet, every group, every
nesting pair is judged — never a sample. The content-keyed cache is what makes
that affordable: an item whose snippet, location, prompt version and taxonomy
are all unchanged keeps its verdict. The cache reduces re-reading, never
coverage. If you are tempted to sample, you have misread this paragraph.

## Definitions (plain language)

- **occurrence / mention** — one place in the site text where a form appears.
- **snippet** — the sentence, or the whole line where there is no sentence
  break, that holds an occurrence. The unit the model is asked about.
- **location** — the model's one sentence saying where that snippet sits.
- **group / record** — all forms whose spelling normalizes alike; the unit every
  later stage reads.
- **nesting pair** — an occurrence sitting strictly inside another collected
  occurrence (`doors` inside `doors and frames`). Only possible since the
  2026-08-27 D8 reversal.
- **BLIND** — a dump with no `fold` block; the stage is invisible in it.

## The protocol

1. **Mechanical pass.**
   `.venv/bin/python checks/run_eval.py --run <run_id>`
   Writes per-field scorecards, `SUMMARY.md`, work orders under
   `history/runs/<run_id>/pending/`, and appends `history/metrics.jsonl`.
   Takes a minute and spends nothing.

2. **Sanity-read before believing any of it.** Open two or three scorecards and
   check the numbers against the dump by hand. **A metric you have not
   spot-checked is not yet a number** (locked lesson: regex sweeps failed three
   times in both directions on this pipeline's prose). Confirm in particular
   that `BLIND` fields really lack a fold block rather than failing to parse.

3. **New subject this run?** If a run contains a subject with no
   `goldens/<slug>/`, seed it first — `GOLDEN_LABELS_SCHEMA.md` has the shape
   and the two-pass promotion rule. Golden labels are derived from the pinned
   text, not from the run, so seeding never waits on a pipeline execution.

4. **Judge fan-out.** One agent per work order
   (`history/runs/<run_id>/pending/<subject>__<field>.json`); split above ~250
   items into slices of 150–200, **never splitting a group's snippets across
   agents** (a group's snippets are read together or its G-codes are guesses).
   Each agent prompt must carry, in this order:
   1. `TAXONOMY.md`'s dimension tables (paste, or give the path).
   2. Its slice of the work order — path plus an explicit index range.
   3. The subject's `goldens/<slug>/subject.yaml` — especially
      `third_party_roster` and `text_hazards`, because S4 (whose words) cannot
      be judged without knowing who else speaks on that site.
   4. The output contract: JSONL, one verdict per item, schema in
      `TAXONOMY.md`, written to
      `history/runs/<run_id>/verdicts/<subject_slug>__<field>[__partN].jsonl`;
      echo `content_key`, `taxonomy_version` and `pv` unchanged; **every item in
      the slice gets a row — no sampling** (a skipped item stays pending
      forever).
   5. The discipline reminders: judge by reading, quote what convicts, an
      `unclear` is honest, and never judge whether the form deserved to be
      searched for (that is the search eval's question).
   Tell agents to build the file with **shell appends in batches**, so an agent
   that dies mid-run still leaves valid JSONL.

5. **Verify before merging.** Re-read, yourself: every S4 fail, every `major`,
   every I1 `diluting`, and five random passes per agent. Mark verified rows
   `"verified": true` and log corrections in
   `history/runs/<run_id>/verification_log.md`. Agents are careful readers, not
   oracles — four of my own numbers were corrected by exactly this step in the
   2026-08-25 census.

6. **Merge and re-score.**
   `.venv/bin/python checks/run_eval.py --run <run_id> --finalize`
   Ingests the verdicts into `history/judgments/`, recomputes rates, rewrites
   the scorecards and appends the trend.

7. **Write `FINDINGS.md`** in `history/runs/<run_id>/`. `SUMMARY.md` is
   regenerated by every mechanical pass, so analysis written there is lost.
   State the headline (location correctness — S2∧S3∧S4), the dilution rate, and
   every tripwire that fired, each with a quote.

8. **Evolve the eval set** — the step that makes this instrument worth keeping.
   New defect classes go to `CANDIDATE_DIMENSIONS.md` with a probe, not straight
   into `TAXONOMY.md`; new golden labels go in as `candidate` with provenance.
   **Promoting a candidate into TAXONOMY.md changes `taxonomy_version` and
   invalidates that field's cached verdicts** — batch promotions between runs,
   never mid-pass, and say so in the report.

## Comparison discipline (binding)

Trend only on **paired identities**: snippets by `mention_id`, requests by
`ud=`, groups by `group_id`, and **always with `chunk_bounds` in the key** —
242 group ids appeared in both chunks of a field on a real run, and a pairing
without bounds silently dropped 114 records.

Unpaired deltas are **upstream drift**, reported as context and never as
mention-stage change. Search phrase sets share only ~43–64% across window
layouts, so a re-chunked run reshuffles this stage's inputs wholesale.

Two runs are comparable only within one `config_digest` (chunk geometry,
normalizer, snippet radius, prompt version). The digest is on every scorecard.

## Noise floors

The Location stage's own reproducibility has **never been measured**. Until
`checks/aa_probe.py` measures it, no location band gates and no location delta
below ~15% relative is reported as a result. For reference, the two floors that
have been measured on this pipeline: freehand grounding reproduces at only
77.7–90.1% on byte-identical payloads, and search's whole-window set identity is
28.4%. Assume this stage's LLM half is no better until shown otherwise.

The mechanical half has **no noise floor at all** — it is deterministic, so its
tripwires are exact and any movement is real.

## Failure modes to respect

- **A `BLIND` field is not a passing field.** It means the dump cannot show the
  stage. Never report its metrics as zeros.
- **`contract_products` is never judged** — it is a byte-copy of `products`
  through this stage. Summing the dump folder overstates by ~32%.
- **Do not re-implement text matching.** `_shared/text_matching` exists because
  this corpus's non-breaking spaces and short forms make naive matchers report
  confident wrong answers; the search harness shipped a false RED on that.
- **The location is evidence downstream.** Grounding and synthesis both read it
  as provenance, so an S4 failure is not cosmetic.
- **A mention/location prompt edit re-digests every synthesis request** and
  voids synthesis's verdict cache. Report the finding; name that cost in the
  report; do not silently trigger it.

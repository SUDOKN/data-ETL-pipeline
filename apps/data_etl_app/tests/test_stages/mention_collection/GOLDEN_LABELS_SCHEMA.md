# Golden labels — what they are, and how one is promoted

The golden corpus is this instrument's ground truth. It is derived **from the
texts**, not from pipeline runs, so it covers all 20 corpus subjects while only
two have ever been through a v3 run. When a run does touch a subject, grading is
immediate and free.

Sibling of `search/EXPECTATIONS_SCHEMA.md`; read that first for the anchoring
conventions this file inherits.

## Semantics (read before adding a label)

**A golden label says what the mention stage SHOULD do with a form, not whether
the form deserved to be searched for.** That second question belongs to
`search/`. A label may therefore describe correct handling of a document title,
a client's product or a polyseme — the handling is in scope, the admission is
not.

**Anchor by quote, not by offset.** The pipeline reads a normalized, page-trimmed
copy of the snapshot; a quote survives that transformation and a character offset
does not. `approx_offset` is advisory, for humans and for narrowing a search.

**One form, three defensible counts — always say which.** `doors and frames` on
steelcraft measures **123** by a whole-word elastic regex over the raw snapshot,
**120** through `collect_window`, and something else again through a hand method.
The gap is not error: the collector blanks URL lines and page-separator lines
(length-preservingly) before scanning, so three occurrences sit on lines the
stage is contractually blind to.

**The collector's number is the authoritative one for an occurrence label**,
because it is what the stage will actually do. That is why
`checks/seed_goldens.py` calls the production `collect_window` rather than a
regex of its own — a golden count taken by a different method grades the stage
against a rule it was never asked to follow. This example carried an invented
`14` until 2026-08-27; a wrong number in a schema's own worked example is the
fastest way to teach a corpus a wrong habit.

**Occurrence labels are computed, not opined.** Where a form occurs is a fact.
They are generated by the same matcher the eval uses, then **sampled and
verified by a reader** — the sample is the label's warrant, and the verification
rate is recorded. Everything else (snippet extent, location, grouping,
inheritance) is a judgment and needs a second pass to be promoted.

## File shape

`goldens/<subject_slug>/subject.yaml` plus one file per field
(all seven always; an empty `labels: []` is required, never omitted — an absent
file is indistinguishable from an unlabelled one).

```yaml
subject: steelcraft.com
field: products
snapshot:
  file: apps/data_etl_app/tests/test_stages/sample_scraped_texts/steelcraft.com.txt
  sha256: <64 hex>
golden_set_version: 1
anchored_on: search/expectations/steelcraft_com/products.yaml   # or "adversarial"
labels:
  - id: steelcraft_com-products-0001
    form: doors and frames
    kind: occurrence            # occurrence | snippet | location | grouping | inheritance
    status: confirmed           # candidate | confirmed | disputed | retired
    expect:
      occurrences: 120          # for kind=occurrence — MEASURED, never guessed
    evidence:
      - quote: Our steel doors and frames set the industry standard.
        approx_offset: 4193
    notes: >
      54 of the 120 are one byte-identical footer blurb, so annotate the label
      `repeated_line` and add a prose quote before treating it as evidence of
      anything about the products.
    provenance:
      - {action: added, by: seed-agent-steelcraft, date: '2026-08-27', source: corpus-seed}
      - {action: verified, by: verify-agent-steelcraft, date: '2026-08-27'}
```

### `expect` by label kind

| kind | `expect` keys |
|---|---|
| `occurrence` | `occurrences` (int), optional `pages` (list of URL), optional `must_not_occur: true` for negative labels |
| `snippet` | `carries` (the sense the clip must preserve, prose), optional `min_span_quote` |
| `location` | `kind_of_text`, `belongs_to`, `whose_words` (one of `site` \| `customer` \| `parent` \| `standards_body` \| `vendor` \| `third_party`) |
| `grouping` | `same_group_as` (list of forms) and/or `different_group_from` (list) |
| `inheritance` | `inside` (the longer form), `verdict` (`sound` \| `diluting`) |

### `subject.yaml`

```yaml
subject: steelcraft.com
subject_name: Steelcraft
snapshot: {file: …, sha256: …}
role: full_unit          # REUSE the search harness's value for the subject
                         # verbatim; it is the same roster and a second
                         # vocabulary would silently fork the corpus.
                         # full_unit | inventory_subject | scale_stress
                         # | out_of_domain_negative | degenerate_input_probe
                         # | attribution_negative | genre_probe
                         # | empty_field_probe
                         # (the last three were added by search on 2026-08-27;
                         # `attribution_negative` names precisely this stage's
                         # whose_words question, so it is kept rather than
                         # flattened. If search adds another, take it and
                         # record the addition here.)
role_source: harvested:search   # or `assigned:<reason>` when none existed
third_party_roster: [Allegion, Falcon, Republic]   # who else speaks on this site
text_hazards:            # things that shape THIS stage specifically
  - {hazard: repeated_footer, note: '44% of lines', quote: '…'}
  - {hazard: country_dropdown, note: '~240-country ISO list from a web form'}
coverage: full_text      # full_text | pipeline_visible_prefix (+ reason)
provenance: [...]
```

## Negative labels are first-class

A form that must produce **zero** mentions is as valuable as one that must
produce fourteen, and this corpus already carries verified examples, found by
the search seeding pass:

- **Substring traps** — `PET` inside "com**pet**itive" (9× on superiortech),
  `ITAR` inside "M**ilitar**y" (9×), `CE` inside Office/Crescent/Certified
  (**1,080×** on howcogroup), `AL` inside almost everything (46,675× on
  acimachine). These are exactly this stage's word-boundary and short-form
  rules, and each becomes an `occurrence` label with `must_not_occur: true`.
- **Zero-occurrence fabrications** — `HDPE`, `LDPE`, `Teflon`, `Bronze` on
  pradeepmetals; `Flame Hardening` on med-tekinc; `Teflon`, `LDPE`, `Acrylic`,
  `Polypropylene`, `PCB` on howcogroup. The stage must find none of them.
  Every one of these claims was re-measured against the pinned text before
  being labelled, and all survived.

**Corrections made while seeding (2026-08-27), kept because the mistakes are
instructive:**

- An earlier draft of this file repeated the claim that `Hemming` matches the
  "HEM Saw" brand 51 times on blackadvtech. **It does not: `Hemming` has zero
  hits of any kind there — it is a pure fabrication.** The 51 false positives
  belong to the three-character form `HEM` (inside "them", "chemical", "hems"),
  and `HEM` is not a negative at all: it genuinely occurs three times as the
  band-saw brand. Two different forms with opposite labels had been conflated.
- `PET` on mathewsco was filed elsewhere as a fabrication; it is a substring
  trap (0 whole-word, 7 inside "competitive"/"compete"). A form that occurs
  nowhere and a form that only *appears* to occur need different labels.
- The historical "`Lead` 52 hits, 0 real" does **not** reproduce on this corpus:
  under the shared matcher `Lead` is a real whole word on 16 of 20 subjects
  ("lead time", "Tin-Lead"). Its defect is **sense**, not occurrence, so it
  belongs to snippet and location labels, not here.

**A matcher limitation found the same way, and deliberately NOT labelled:**
`TIG` scores zero on howcogroup because the site writes "**TiG**", and both the
shared matcher and the pipeline's own scan force case-sensitive matching for
forms of three characters or fewer. That rule is right far more often than it is
wrong (it is what stops "tight" counting as TIG), but here it costs a true
occurrence. Labelling it `must_not_occur` would enshrine a matcher artifact as
ground truth, so it is recorded in `BOUNDARY.md` instead.

## Status lifecycle

Agents and the assistant add labels as `candidate` with provenance. Promotion to
`confirmed` — the only status that gates — requires a **second independent pass**
re-reading the text and agreeing; the promotion is a provenance row. The user may
veto or mark `disputed` at any time, and `disputed` never gates. Retire, never
delete, labels that turn out wrong, with a provenance row saying why. Every
reported number states the `golden_set_version` it was computed against.

**The lesson that makes this rule non-negotiable:** the search harness fired a
false RED because its own eval set scored correct restraint as a recall failure —
the equipment prompt explicitly excludes metrology, and six metrology entries had
been seeded as must-find. Seed to what the stage is actually asked to do, not to
the plain meaning of a field's name.

## Two deliberate leniencies

**Occurrence counts tolerate the page-trim.** A form whose only extra occurrences
sit on an excluded legal page is not a miss; the label records the trimmed
expectation and notes the untrimmed one.

**Location labels grade the three elements independently.** A location can name
the right section and the wrong speaker; collapsing them into one verdict would
hide the failure that matters most downstream (`whose_words`, which both
grounding and synthesis read as provenance).
